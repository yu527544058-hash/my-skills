# aht-target Skill 使用指南

# **背景**

项目运营需要对新项目在项目开始前设定AHT目标，且在项目运行中根据数据变化（如有），及时调整目标，确保项目产能规划的时效性与准确性。根据以往项目的经验，数据层面的常见影响因素，包括：

- 文本项目：字数的增加/减少

- 视频项目：视频的时长变化、视频质量的变化（例如：音轨不清晰导致 AHT 增长）

> 时长、字数这类可量化的因素可直接纳入测算。音轨质量、内容难度这类因素无法归结为单一数值，本 skill 不会自动识别，只能通过"同一 case 由不同人处理"的对比间接反映。

# **目标**

此skill旨在

- 依据实测数据测算 AHT 目标，并在数据构成变化时重新测算，以保证测算的准确性

- 判断 AHT 差异的来源：来自 case 本身（长短、难易），还是来自标注员个体差异

# 安装方式

1. 在 Claude Code，或贵司内部的 AI 助手中使用本 skill

2. 安装"aht-target" skill（skill链接：https://github.com/yu527544058-hash/my-skills）

3. 安装完成后，输入 `/aht-target help` 可查看本说明，能正常显示即表示安装成功

4. 按照使用场景调用

    1. 说明详细使用场景，项目背景，并提供数据细节

    - 例如：用于「新项目AHT设定」，需提供

        - 此项目AHT影响因素

        - 试标数据，包括

            - Case ID

            - 每条case AHT

            - 每条case AHT影响因素数值

            - 标注顺序（如有）： 用于识别熟悉期。试标前几条因尚未熟悉规则，AHT偏高，测算时需剔除

# 使用场景

## 场景一：新项目定标

### **确认影响AHT因素**

> 你的项目中，什么因素越多、处理越耗时？ 这即是影响处理时间的主要因素，以下统一为**影响因素**，其取值在测算公式中简称"长短"

|**项目类型**|**AHT影响因素取值**|**单位**|
|---|---|---|
|视频类|视频时长，或 segment 数|秒 / segment|
|文本类|文本字数|字|
|图片类|图片张数|张|

### **测算原理**：每条处理时间 = 起步时间 + 每单位增量 × 长短

- **起步时间**：与长短无关的固定耗时（打开、加载、查看要求、检查、提交）

- **每单位增量**：长短每增加一个单位所增加的耗时。视频为"每秒增加若干秒"，文本为"每 100 字增加若干秒"，图片为"每张增加若干秒"

    - 文本类示例：起步时间 1 分钟，每 100 字增加 12 秒，则 500 字的 case 需 2 分钟，2000 字的 case 需 5 分钟。

### **操作流程**：

|**项目阶段**|**POC输入**|**Skill 输出**|
|---|---|---|
|启动前的定标|试标数据（20-30 条）：<br>- Case ID、<br>- 影响因素取值（视频时长 / segment 数 / 字数 / 张数）<br>- AHT<br>- 标注顺序（用于识别熟悉期。试标前几条因尚未熟悉规则，AHT偏高，测算时需剔除）|起步时间、每单位增量、基线 AHT|
|稳定产出后|标注员的实际数据|基于标注员实际水平的测算结果，同时调整AHT目标|
|后续AHT调整（如需）|该批次的平均长短（平均时长 / 平均字数等）|该批次的 AHT 目标|

**试标注意事项**：

- 样本最好要涵盖短、中、长三档，以此以确保估算估算每单位增量

- 前 3–5 条为一般为熟悉期，耗时偏高，建议剔除；如无法确定，skill会自动识别

## 场景二：现有项目AHT目标调整

> **示例问法**："长case 占比从 7% 升至 12%，AHT 目标应调整为多少"

|**POC输入**|**Skill输出**|
|---|---|
|**项目基本信息**<br>- 标注内容<br>- AHT影响因素<br>- 长case的定义<br>> **长 case 的定义**：影响因素取值超过设定标准的 case，例如"超过 30 个 segment""超过 2000 字""超过 20 张图"。<br>> <br>> **注意**：长 case 占比与长 case 平均时长须依据同一标准计算，否则两个数据无法对应。<br>> <br>> <br>- 当前AHT设定情况（即：当前AHT基线是否包含长case）|- 调整后的目标值和合理的范围<br>- 换算公式：占比每上升 1 个百分点，目标增加的秒数<br>- 数据中存在的问题：挂机记录、缺失、统计标准不一致|
|**长case实际数据**<br>- Case ID<br>- 影响因素取值（segment 数、字数、张数或视频时长等）<br>- AHT<br>- 标注员||

## 场景三：AHT波动的归因分析

> **示例问法**："帮我分析这批数据的 AHT 差异由什么造成"

|**POC输入**|**Skill 输出**|
|---|---|
|**实测数据**<br>- 全部 case 或仅长 case 均可<br>- 需包含**标注员**与 **case ID** 两列信息。若同一 case 曾由两人分别处理，可直接测算换人后的耗时倍数。|- 差异中来自 case 本身与来自处理人的比例<br>- 各标注员相对同批 case 平均水平的快慢<br>- 异常记录（例如单条 case 耗时 3 小时）|

---

**数据格式**

- **建议提供 CSV。** 截图亦可，但请避免过度压缩，否则仅能读取汇总行

- **列名中英文均可**：case ID / 视频时长 / 字数 / 图片数 / segment / AHT / 标注员 / 顺序

- **视频时长可填秒数或 `mm:ss`，字数填数字即可**，含千分位逗号（1,200）亦可识别

- **无有效时间的记录请予保留**，例如挂起（deferred）、质检中（In check）、无记录（Not found）。各平台状态名称不同不影响识别，该单元格为空或填写非数字内容均计为无效。本skill会单独检查此类记录是否集中于长 case，若是，目标将被低估

# 常见Q&A

1. **结果为何附带一个范围？**

样本量有限，真实值大概率落于该范围内。如需预留余量，可取范围上限。

2. **占比上升是否一定要增加时间？**

通常情况是。若长 case 本身的长短或难度同时上升，需要增加的幅度会更大。本skill会对此进行检查。
