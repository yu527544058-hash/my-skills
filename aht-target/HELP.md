# aht-target 使用指南

**【背景】** 标注项目需为每条 case 设定处理时间目标（AHT）。当 case 构成发生变化——长 case 占比上升、视频时长增加、文本字数增加——原有目标不再适用。

**【目标】**
- 依据实测数据测算 AHT 目标，并在 case 构成变化时重新测算
- 判断处理时间差异的来源：来自 case 本身，还是来自处理人

## 术语说明

| 术语 | 含义 |
|---|---|
| **AHT** | 平均每条 case 的处理时长（Average Handling Time），单位一般为秒 |
| **长短** | 影响处理时间的主要因素，即判断长 case、短 case 所依据的数值：视频取时长或 segment 数，文本取字数，图片取张数。不包含处理人的效率差异 |
| **长 case** | 长短超过设定标准、耗时较长的 case，例如超过 30 个 segment、超过 2000 字 |
| **segment** | 视频切分后的片段，一条视频可能包含数十个 |
| **基线** | 设定目标的起点，例如"当前每条 500 秒" |
| **试标 / 定标** | 项目正式开工前，由项目经理先完成一小批，用于测算时间目标 |
| **正式生产** | 项目正式开工后，由标注员执行的作业 |
| **挂机** | 任务处于打开状态但无人操作，记录时长高于实际作业时长 |

## 使用方式

- 以中文向 Claude 说明需求，并提供数据表即可，**无需自行执行任何命令**
- 输入 `/aht-target help` 查看本说明
- 示例问法："帮我测算 AHT 目标"、"长 case 占比升至 15% 需要给多少时间"、"新项目如何定标（视频按时长、文本按字数）"

## 适用场景

### 场景一：长 case 占比变化后的目标调整

**长 case 的定义**：长短超过设定标准的 case。长短依项目类型而定，视频取时长或 segment 数，文本取字数，图片取张数。标准由你们自行确定，例如"超过 30 个 segment""超过 2000 字""超过 20 张图"。

**示例问法**："长 case 占比从 7% 升至 12%，AHT 目标应调整为多少"

**需要明确的两项前提**（最易出错之处）：

1. **当前 AHT 基线是否包含长 case。** "500 秒为不含长 case 时的水平"与"500 秒为当前全部 case 的平均值"，两者含义相反，会导致调整方向相反
2. **长 case 的判定标准。** 占比与长 case 平均时长须依据同一标准计算，否则两个数据无法对应

**建议提供**：长 case 的逐条明细（case ID、长短、AHT、标注员）。长短即判断长 case 所依据的数值：segment 数、字数、张数或视频时长。格式以 CSV 为佳，截图亦可。

**输出内容**：
- 调整后的目标值及合理范围
- 换算公式：占比每上升 1 个百分点，目标增加的秒数
- 数据中存在的问题：挂机记录、缺失、统计标准不一致

### 场景二：新项目定标

**首先确认：你的项目中，什么因素越多、处理越耗时？** 这即是影响处理时间的主要因素，以下统称"长短"：

| 项目类型 | 长短取值 | 单位 |
|---|---|---|
| 视频类 | 视频时长，或 segment 数 | 秒 / segment |
| 文本类 | 文本字数 | 字 |
| 图片类 | 图片张数 | 张 |

**测算原理**：每条处理时间 = 起步时间 + 每单位增量 × 长短

其结构与出租车计费一致：起步价 + 每公里费用。

- **起步时间**：与长短无关的固定耗时（打开、加载、查看要求、检查、提交）
- **每单位增量**：长短每增加一个单位所增加的耗时。视频为"每秒增加若干秒"，文本为"每 100 字增加若干秒"，图片为"每张增加若干秒"

文本类示例：起步时间 1 分钟，每 100 字增加 12 秒，则 500 字的 case 需 2 分钟，2000 字的 case 需 5 分钟。

**实施步骤**：

| 阶段 | 需提供 | 输出 |
|---|---|---|
| **定标** | 项目经理试标数据（不超过 30 条）：case ID、长短（视频时长 / segment 数 / 字数 / 张数）、AHT、标注顺序；以及正式生产时的平均长短 | 起步时间、每单位增量、基线 AHT |
| **正式生产 2–3 天后** | 标注员的逐条数据（增加标注员一列） | 基于标注员实际水平的测算结果，以及标注员与项目经理的效率比值 |
| **后续每批** | 该批次的平均长短（平均时长 / 平均字数等） | 该批次的 AHT 目标 |

**列名直接使用"视频时长""segment""字数""图片数"即可**，本技能会自动识别单位。

**试标注意事项**：

- 样本需覆盖短、中、长三档，最长者不应低于最短者的 2 倍，否则无法估算每单位增量
- 前 3–5 条为熟悉期，耗时偏高，建议剔除；如无法确定，本技能会自动识别
- **正式生产后的重新测算不可省略**：项目经理个人的速度与标注员可能存在较大差异

### 场景三：处理时间波动的归因

**示例问法**："帮我分析这批数据的 AHT 差异由什么造成"

**需提供**：逐条明细，全部 case 或仅长 case 均可。其中**标注员**与 **case ID** 两列最为关键。若同一 case 曾由两人分别处理，可直接测算换人后的耗时倍数。

**输出内容**：
- 差异中来自 case 本身与来自处理人的比例
- 各标注员相对同批 case 平均水平的快慢
- 异常记录（例如单条 case 耗时 3 小时）

## 数据格式

- **建议提供 CSV。** 截图亦可，但请避免过度压缩，否则仅能读取汇总行
- **列名中英文均可**：case ID / 视频时长 / 字数 / 图片数 / segment / AHT / 标注员 / 顺序
- **视频时长可填秒数或 `mm:ss`；字数填数字即可**，含千分位逗号（1,200）亦可识别
- **无有效时间的记录请予保留**，例如挂起（deferred）、质检中（In check）、无记录（Not found）。各平台状态名称不同不影响识别，该单元格为空或填写非数字内容均计为无效。本技能会单独检查此类记录是否集中于长 case，若是，目标将被低估

## 常见问题

**测算结果可否直接用于个人考核？**
不建议。该结果为排产与人力测算所用的平均值。同一 case 换人处理经常相差 2 倍，以平均值考核将导致约半数人员无法达标。

**数据量需要多少？**
试标 20–30 条即可看出规律。如需判断人员之间的差异，建议 50 条以上，且包含同一 case 由多人处理的记录。

**结果为何附带一个范围？**
样本量有限，真实值大概率落于该范围内。如需预留余量，可取范围上限。

**占比上升是否一定要增加时间？**
通常是。若长 case 本身的长短或难度同时上升，需要增加的幅度会更大。本技能会对此进行检查。

## 自动检查项

- 统计标准不一致：占比与长 case 平均时长未按同一标准计算
- 单条记录明显异常，疑似挂机
- 测算情形超出现有数据范围，结果仅为估算
- 数据量不足，结论可靠性有限
